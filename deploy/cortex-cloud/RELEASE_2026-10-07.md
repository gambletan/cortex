## Rollback

The previous container is retained, stopped, as `cortex-cloud.rollback-461ad11`, with
its previous image, command, environment, and mounts. Configuration backups are under
`~/cortex-cloud/releases/461ad11`; the initial domain setup backup is under
`~/cortex-cloud/releases/domain-20261008T010654Z`. These are configuration backups, not
copies of tenant data or the master key. This release introduced no database-schema
migration.

On the deployment host, restoring the previous container restores both its image and
its original base URL:

```bash
docker stop --time 30 cortex-cloud
docker rm cortex-cloud
docker rename cortex-cloud.rollback-461ad11 cortex-cloud
docker start cortex-cloud
curl --fail http://127.0.0.1:8084/healthz
```

The dedicated TLS site can remain available during rollback; the legacy issuer is
restored by the previous container. Clients authorized under the newer issuer would
need to reconnect again. No rollback was necessary for this release.
