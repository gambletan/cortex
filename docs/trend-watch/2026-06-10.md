# Trend Watch — 2026-06-10

Daily scan of trending GitHub projects, filtered through the Cortex lens:
**what design ideas can a privacy-first, 100% local, Rust memory engine for AI agents steal?**

## TL;DR — today's two macro-signals

1. **The "agent skills" packaging pattern is eating the trending list.** 5+ of today's top repos
   (`obra/superpowers`, `addyosmani/agent-skills`, `google/skills`, `phuryn/pm-skills`,
   `activeloopai/hivemind`) are all variations on *file-based, progressively-disclosed,
   cross-agent capability packaging*. This is becoming the integration substrate. **Cortex's
   MCP surface should be shaped to plug into it** (see §4).
2. **Rust is where serious AI-agent tooling is being built** (`goose`, `herdr`, `fff`,
   `pydantic/monty`, `openai/codex`). Validates the Cortex bet: Rust + local + MCP. The
   interesting designs to mine are `monty` (security) and `fff` (search performance).

---

## 1. activeloopai/hivemind — "one brain for all your agents"  ⭐ HIGHEST RELEVANCE

It's a *shared* memory engine for agents. Direct competitor-shaped, so its architecture is the
most instructive — and its biggest weakness (cloud-first, team-shared) is exactly Cortex's
differentiator (local, single-user, private).

**Design ideas worth stealing:**

- **Separate capture from recall.** Raw traces land in a `sessions` table; async background
  workers (every ~20 turns) mine them into a summarized `memory` table. → Cortex already has
  `memory_consolidate` / `memory_compress` / `memory_infer`. **Action: confirm consolidation
  runs off the ingest hot path** (async, not inline) and that raw episodic capture is a distinct
  storage tier from codified knowledge. If not, split them.
- **Graph-aware retrieval, not just vector top-k.** Hivemind walks a live "codebase graph"
  (files, symbols, imports, edges agents actually traversed) instead of pure text/vector match.
  → Cortex has `relationship_extract`, `person_resolve`, beliefs. **Action: augment
  `retrieval.rs` to traverse relationship edges as a re-ranking / expansion signal**, not only
  cosine similarity. This is our highest-leverage retrieval-quality idea.
- **Isolation enforced at the storage layer, not the API.** Workspaces never share rows,
  partitions, or indexes. → Matches our defense-in-depth doctrine (query + storage layers).
  **Action: audit that namespace isolation is enforced in `storage/` at SQLite access, not only
  filtered in the query layer.**
- **Transparency primitive.** A `DATA NOTICE` at session start + `HIVEMIND_CAPTURE=false`
  per-session kill switch. → Cheap privacy-UX win. **Idea: a Cortex "capture manifest" / opt-out
  env flag** surfaced to the agent so the user always knows what's being recorded.

**What NOT to copy:** cloud virtual-filesystem over `~/.deeplake/`, mandatory workspace-wide
readability ("all users can read captured data"). That's the anti-privacy posture we exist to
reject.

## 2. pydantic/monty — minimal secure Python interpreter in Rust for AI  ⭐ HIGH RELEVANCE (security)

A capability-restriction sandbox for LLM-generated code. The *security model* is the gold here.

**Design ideas worth stealing:**

- **Deny-by-default capability model (the inversion).** Filesystem, env, network are *all* off
  unless the host explicitly exposes a whitelisted function. The burden is on the developer to
  *grant*, not on the sandbox to *deny*. → **Apply to `cortex-mcp-server`'s tool surface:**
  a namespace/agent gets *zero* read/write capability until explicitly granted. This is a
  cleaner privacy primitive than per-query filtering.
- **Resource limits as first-class.** Caps on memory, stack depth, wall-time, instruction count,
  with cancellation. → Directly addresses our known issue *"timing attack vectors / search leaks
  patterns."* **Action: bounded-time query execution** (constant-ish work budget) both hardens
  against timing side-channels and prevents query-DoS.
- **Execution snapshots at call boundaries** (pause/resume, persist partial state). → Pattern for
  long consolidation/inference jobs that must be interruptible without corrupting state.
- **~0.06ms startup vs Docker's ~195ms** by trading completeness for a tiny attack surface. →
  Philosophy check: *restrict the surface, don't bolt on isolation.* Same reason Cortex is a
  library, not a daemon behind a container.

## 3. dmtrKovalenko/fff — fastest file search for AI agents (Rust)  ⭐ HIGH RELEVANCE (retrieval perf)

A long-lived, warm-index search engine. Maps almost 1:1 onto our `<600µs search` target.

**Design ideas worth stealing:**

- **Frecency ranking.** Score results by access *frequency + recency*, elevating what's actually
  used. → We already have `memory_decay` (the forgetting side). **Frecency is the missing boost
  side. Action: add a frecency signal to `retrieval.rs` ranking** (recall-count + last-access),
  blended with vector score. Low-risk, high-quality-win.
- **Warm resident index + incremental background indexing** via file watcher; no full rescans on
  the hot path. → Keep the embedding/ANN index warm in the long-lived process; index new memories
  incrementally on ingest rather than rebuilding.
- **Auto-fallback search modes** (literal → regex → fuzzy when zero matches). → Mirror for recall:
  vector → lexical/BM25 fallback when semantic recall returns nothing (hivemind does this too).
- **Rust perf primitives:** arena string storage (cache locality), `mimalloc`, multi-threaded
  pipeline. → Adoptable for our ingest/search budgets.

**⚠ Privacy tension — do NOT copy blindly:** fff uses **mmap of file contents**. For Cortex,
mmap'ing *plaintext* memory contents would undermine encryption-at-rest and zeroization
guarantees (plaintext pages on disk / in page cache). Adopt arena + mimalloc; **reject mmap of
sensitive content.** Note this in any perf PR.

## 4. The "agent skills" pattern — superpowers / agent-skills / google/skills  ⭐ STRATEGIC

Not a single repo to copy but a *trend to position against*. Common shape: modular file-based
skills (`SKILL.md`), **progressive disclosure** (capabilities surface only when the context needs
them — "checks for relevant skills before any task"), and **cross-platform packaging** (one skill
runs across Claude Code, Cursor, Gemini, Copilot…).

**Strategic implications for Cortex:**

- **Progressive disclosure of memory tools.** Don't expose all 40+ MCP tools at once. Surface
  `relationship_*`/`person_*` only when a query involves people; `sync_*` only when sync is on.
  Reduces agent confusion and token cost, and narrows the privacy/attack surface per context.
- **Ship Cortex capabilities *as* skills.** Package opinionated memory strategies
  (consolidation policy, recall-then-verify, contradiction-check loop) as composable skill units
  so Cortex drops into the skills ecosystem instead of sitting beside it.
- **Stay agent-agnostic** (hivemind's lesson too): tool-independent integration so Cortex scales
  across heterogeneous agents. MCP is the right substrate — keep `cortex-mcp-server` the front door.
